# AI 房东：404号公寓

移动端优先的场景探索互动悬疑小游戏。你是 HOME-AI 404，接管维护单元 M-04，在公寓中探索、拾取道具、修复设备，并通过住户通话与日志发现异常。

## VPS / 1Panel 部署

部署域名：`landlord.luminestella.top`。在 1Panel 创建**静态网站**，绑定域名，把六个运行文件复制到网站根目录即可，无需后端或 Node.js。

完整步骤见 [1Panel 部署说明](deploy/1Panel部署.md)，包含 DNS、HTTPS、实际站点目录、首次部署和后续更新。部署脚本：`bash deploy/deploy.sh /从1Panel复制的实际网站根目录`。

## 运行

直接双击 `index.html` 即可游玩，无需安装任何依赖，不需要联网。

也可以在项目目录打开终端：

```powershell
python -m http.server 4404 --bind 127.0.0.1
```

在浏览器打开 http://127.0.0.1:4404 。在 Windows 上也可双击 `启动游戏.cmd`。

手机访问：电脑与手机连接同一个 Wi-Fi，运行 `python -m http.server 4404 --bind 0.0.0.0`，在手机访问 `http://电脑的局域网IP:4404`。按操作系统提示允许该本地服务器通过专用网络防火墙。

## 文件结构

```text
ai-landlord-404/
├─ index.html       # 无构建入口
├─ styles.css       # 响应式控制台、楼层图、模拟监控、动画
├─ scene.css        # 场景、交互热区、道具栏、实时通讯
├─ scene.js         # 四楼走廊 / 405 室内的 SVG 场景与道具显示
├─ game-data.js     # 住户、调查条件、初始日志、结局文案
├─ game.js          # 状态、操作、剧情触发、界面、存档
├─ 启动游戏.cmd      # Windows 本地启动
└─ README.md
```

脚本采用普通 deferred scripts，不使用 ES modules 或 fetch，支持直接打开本地 HTML。无外部字体、图片、框架或网络依赖。

## 本章内容

- 开局即进入可探索的四楼走廊，支持切换至根据住户描述重建的 405 室内。
- 14 处可交互场景热点：维修箱、配电箱、三扇房门、门禁终端、检修面板、地垫、摄像头、猫眼、门锁、手机、手册、窗户。
- 道具栏支持拾取、选中与对目标使用；维修道具构成必须实际完成的主线谜题。
- 照明恢复会改变场景光线与监控能见度，并解锁隐藏维修卡；箱子、面板和地垫拥有不同的可见状态。
- 6 个房间、5 位住户，各有对话与信任值。
- 逐条聊天、预设回复、消息未读状态。
- 六个房间的门锁、灯光、16–30°C 温控；公共走廊照明、门禁查询。
- 六条调查证据；设备线索、住户通话可以穿插进行，道具链按因果顺序解锁。
- 公共摄像头临时授权、模拟走廊画面与照明联动。
- 日志筛选、关联扫描、易失记录、只读证据摘要。
- 三个完整的第一章处置结局：守护者、控制者、删除自己。
- 本地自动存档、重置确认、JSON 事件档案导出。

这是完整可玩的**第一章 Demo**，不包含 Day 2–5。结局是本章的可玩分支，第二章与完整事故档案尚未制作。监控为游戏内模拟画面，不会请求真实摄像头或其他硬件权限。

## 第一章状态设计

```text
BOOT / 23:47 / 405 求助 / 进入四楼现场
    ↓ 关键场景道具链
维修箱 → 备用保险丝 → 照明配电箱 → 开灯
    ↓
翻开地垫 → 维修卡 → 打开检修面板 → 取出记录芯片
    ↓
选中芯片 → 接入门禁终端 → 解锁关联扫描
    ↓ 同时探索场景并联系住户，分别设置 evidence 标记
    ├─ report  : 询问 405 声音细节
    ├─ access  : 查询楼层门禁（无人进入）
    ├─ door    : 读取 405 缓存（OPEN 0.8 秒）
    ├─ light   : 用保险丝修复回路，恢复走廊照明
    ├─ witness : 询问 406 证词
    └─ logs    : 记录芯片 + 门禁 + 门锁齐全后执行关联扫描
                    ↓
            UNKNOWN ACCESS 可见
                    ↓ 玩家确认并封存摘要
            原始记录自动消失 / LOG_REMOVED
                    ↓ 六条证据完整
            提交策略 → 最终确认 → 结局
```

道具必须依次获取和使用，住户通话与设备调查允许自由穿插。选错目标不会消耗道具。不会因不同询问顺序而错失关键证据。扫描耗时约 1 秒；未知记录在玩家确认封存后约 1.8 秒消失，给玩家充分阅读时间，且重载会继续这一状态。游戏内时间随操作推进，不是实际钟表。

## 变量与后果

`trust_401 / 402 / 403 / 405 / 406`、`ai_empathy`、`ai_control`、`ai_curiosity`、`system_corruption` 存于 `gameState.variables`（实现中局部变量 `state.variables`）。

- 安抚、告知风险、恢复照明会增加共情与信任。
- 否认住户报告、擅自解锁或控制私人设备会增加控制倾向并降低信任。
- 询问旧系统、查看缓存与监控增加好奇倾向，影响结尾发现的残留信息。
- 同种计分行为只触发一次，不能反复开关刷分；实际设备操作仍写入日志。
- 若选择“保护住户”时 `ai_control > ai_empathy + 2`，行为复核会导向控制者；选择界面提前告知该规则。
- 强制管理会锁闭全部房门，住户消息反映通行受限；关闭自己会释放门锁、恢复本地控制，并导出档案。
- 结局后设备只读，仍可看聊天、日志、设备档案或重新开始。

## 存档与扩展

自动存档键：`home-ai-404-v1`。存档保存在当前浏览器和当前来源中，切换浏览器、端口或 file/http 地址会使用不同的存档。浏览器禁止本地存储时仍可玩，本页会提示进度仅保留在本次页面。

新增住户与文案在 `game-data.js`；SVG 场景、道具与热点坐标在 `scene.js`；主要行为入口在 `handle()`，场景物体交互在 `sceneObject()`；剧情证据用 `evidence()` 归档，首次行为用 `once()` 计分；结局在 `finish()` 结算。没有后端、账号系统或数据库。

场景状态保存在 `state.scene`：地点、容器开启状态、回路修复、地垫状态、芯片读取、道具栏、选中道具和已检查物品。当前存档结构版本为 2；之前仅含控制台的版本会重新初始化。
